Enhancement Narrative

Read the Software Design and Engineering Narrative

The Travlr application was enhanced to improve administrative trip management and application reliability. The Trips page supports searching by trip name and filtering by trip length and price range. The interface also displays trip images, making travel records easier to identify. In addition, price validation prevents administrators from submitting negative per-person prices. These improvements demonstrate skills in Angular component development, TypeScript, reactive forms, REST API integration, MongoDB/Mongoose data management, JWT-based authentication, and software testing. Testing included searching for a trip by name, clearing filters, verifying image display, and confirming that invalid negative prices are rejected while valid prices are accepted. The enhancement demonstrates how thoughtful interface design, validation, and integration improve the usability and reliability of an existing software solution.

Algorithms and Data Structures

Artifact Description

The enhanced Travlr administration interface uses a TypeScript array to store the retrieved trip records and the `Array.filter()` method to select records that match the administrator's search criteria. The filtering logic supports trip-name searches, trip-length filtering, and minimum and maximum price constraints. Multiple criteria can be applied together, and the interface displays the matching results and handles cases where no records match. For a collection of \(n\) trips, the filtering operation has \(O(n)\) time complexity because each trip may need to be examined. The result collection requires additional space proportional to the number of matching records. This approach is understandable and appropriate for the current dataset, although database-level filtering or indexing could be more efficient for substantially larger datasets.

Enhancement Narrative

Read the Databases Narrative

The database enhancement improves the integrity of Travlr trip-pricing data by preventing negative per-person prices. The Angular form validates the price before submission, while the Mongoose model enforces a minimum value of zero at the data-model level. This layered validation helps protect stored data rather than relying exclusively on client-side checks. Testing covered three boundary cases: a price of -50 was rejected, a valid price of 500 was saved successfully, and a price of 0 was accepted. These tests demonstrate the importance of data validation, consistent business rules, and maintaining data integrity throughout the application's CRUD workflow.
